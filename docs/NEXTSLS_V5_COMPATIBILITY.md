# NextSLS V5 通用接入与兼容策略

2026-11-18。本次策略按管理员明确授权升级；旧版规则及 photos 的“待确认即阻断”不再作为统一默认策略。

## 一套引擎、按账号隔离

代理管理的“NextSLS V5 快速接入”只接收名称、HTTPS NextSLS 租户域名、App Token。受保护的管理员 POST 路由读取 docs 和 Markdown（不带 Token），用该账号自己的 Bearer Token 调用 get_services，识别响应、保存独立渠道及规则后才提交新账号。认证失败不留下半个账号，名称或同租户同 Token 重复时不覆盖旧记录。App Key、客户代码、旧轨迹 URL 不参与 V5 新账号必填校验。原高级代理编辑及非 V5 流程保留。

域名/Token 通过 get_services 的真实 V5 成功响应验证；文档不可读取会记录为不可用，不能冒充已读。快速接入的成功不代表任何真实运单已经创建。界面显示认证、文档读取、渠道未知规则数量及未进行真实写入的状态。

## 通用图片默认

`photos` 和 `photo_url` 都使用已有星睿文件发布器产生的完整 HTTPS URL 字符串。复用 `nextsls.product_photo_url`，不使用供应商名称或域名白名单，不使用 Base64/JSON数组/文件ID，不相互替换字段。只按当前字段要求发送；声明规则未知时，可自动附上已有且逐行完整匹配的商品图，明确这是通用预备资料，不能视为渠道确实要求或已接受。

每条商品图必须来自对应原 Excel 申报行，指纹、类型、字节及发布验证沿用已有安全模块。正常创建使用订单归属签名快照；预检使用无客户关联的独立文件。图片与packing.xlsx共用HTTPS服务，不依赖AWS。

真实 status=0 若明确指出 photos 不支持URL，将保存脱敏的该渠道协议差异。普通“photos必填”、URL过期或无法判断的响应不被当成编码不兼容证据。例外属于该账号渠道配置，不能影响同供应商其他渠道或其他账号。默认编码预检通过不等于供应商真实创建确认。

## 新版、旧版、部分规则

`nextsls.preparation_rules` 统一处理完整或部分 get_services 结构。

| 信息 | 保存形式 | 行为 |
| --- | --- | --- |
| 明确返回的申报列表和0/1标志 | 原含义规范化 | 强制校验实际返回的要求 |
| 未返回或null的申报列表/标志/发件要求 | null + unknown_rules字段名 | 未知，不写成空列表或0；允许预览 |
| 非法的已返回规则值 | 协议错误 | 刷新提示错误；真实创建前再次读取并拒绝无效规则 |
| 基础V5字段 | 固定公共结构 | 中英文品名、地址、箱货对应、真实数量/价值/重量尺寸继续校验 |

未知申报列表时，已有真实品牌、型号、SKU、商品重量尺寸、ASIN/FNSKU及经确认的Amazon参考号可以发送；未核实PO、FBA号和占位值不能冒充参考号。后台提供可选真实资料补充入口，标明不代表全部必填。已知规则仍严格要求缺项；未来供应商不需要专属创建程序。

未知装箱单要求时，文件服务可用则附上自动生成的通用下单文件；其规则仍是null，不能声称供应商已认可此附件。发件要求未知时只发送已配置且结构有效的真实发件地址，不生成占位地址。

## 管理员逐票授权与结果处理

预览和附件验收不需要开启真实创建。页面区分通用预检、未知规则首次待验证、已有真实创建成功记录。可下载受保护的完整JSON预览；其中签名URL仅对管理员显示，响应禁止缓存，不能复制到公开日志。

真实创建仍须站点许可、管理员、审核通过、当前订单版本及单票授权。规则未知时还必须勾选额外确认并写核对依据。授权绑定账号、租户、渠道、订单版本、30分钟有效期和规范化规则指纹；刷新得到的未知/已知要求改变时要求重新确认。核对依据保存在订单授权历史和提交审计，不标记“事先验证兼容”。

请求前先读取该账号实时get_services，核对身份和规则，构造真实资料、准备文件、预留唯一参考号并提交数据库防重状态，再仅发一次 shipment/create。成功保存 data.shipment.shipment_id。明确拒绝保存脱敏字段信息；超时、无法解析或写回不明均锁定，禁止自动重发。后续必须按唯一客户参考号对账并按现有业务核实流程处理。

本轮不发送任何新真实shipment/create，站点数据库许可关闭，CREATE_ENABLED=0；BC081190及所有历史订单关联保留，不修改Koyeb。

## 从新账号到创建回写的工程验收

后续验收增加了两个从零接入的隔离账号（动态分配 ID 13 和 100，分别为完整规则和旧版规则）。测试走正式管理员路由：三项接入、客户上传、供应商级联、审核、页面启用许可、逐票授权、同一send_order、真实文件模块生成签名URL、模拟供应商读取图片及XLSX、返回单号、数据库回写及同账号get_info身份核对；重复点击只发送一次。只模拟远端HTTP，不创建供应商生产运单，也不把这两个合成单号当成真实供应商证明。

“无型号”由管理员明确确认后适用于所有V5账号。既有经核实的客户发票PO特殊来源映射保存在nextsls_declaration_contracts.json及账号配置数据中，创建函数不再按搏诚域名分支。普通新账号仍可用订单级真实参考号及PO确认，无须增加源代码分支。

经用户后来明确授权，可把已成功订单的原发票作为其他供应商的接口测试样本。验收准备工具只创建独立待审核副本，不创建供应商运单，不授予创建权限：只修改副本D4为唯一XR-QA测试参考号，原FBA参考、原文件指纹及授权依据保留为来源；原文件和WPS图片字节保留。明确标记不安排揽收或发货，原供应商授权及Amazon PO渠道确认不继承，销售报价仅复制为待审核草稿。仍必须通过正式管理员审核、逐票授权和确认才会调用创建接口。
